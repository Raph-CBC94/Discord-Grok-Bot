# Discord Grok Bot\n\nBot Discord qui répond lorsqu'il est mentionné et utilise l'API Grok/xAI pour générer ses réponses. Il récupère jusqu'à 20 messages précédents du salon pour fournir du contexte.\n\n## Variables d'environnement\n\nObligatoires :\n\n- DISCORD_TOKEN\n- GROK_API_KEY_1\n\nOptionnelles : GROK_API_KEY_2 à GROK_API_KEY_10, GROK_MODEL, GROK_BASE_URL, GROK_REQUEST_TIMEOUT_MS, PORT.\n\nVoir .env.example. Les valeurs réelles doivent être saisies dans les variables d'environnement de l'hébergeur, jamais dans GitHub.\n\n## Discord\n\nDans le portail développeur Discord :\n\n1. Créer une application et ajouter un bot.\n2. Activer Message Content Intent dans les intents privilégiés.\n3. Inviter le bot avec les scopes bot et applications.commands.\n4. Accorder au bot View Channel, Read Message History et Send Messages.\n\n## Développement local\n\npnpm install\npnpm --filter @workspace/discord-bot run dev\n\n## Déploiement recommandé : Railway\n\nCe bot utilise la Gateway Discord, une connexion persistante. Il doit fonctionner comme un service long-running.\n\n- Build command : pnpm --filter @workspace/discord-bot run build\n- Start command : pnpm --filter @workspace/discord-bot run start\n- Root directory : /\n\nAjoutez les variables d'environnement dans Railway. Ne définissez pas PORT manuellement si Railway le fournit automatiquement.\n\n## Vercel\n\nVercel n'est pas adapté pour maintenir le bot Discord en ligne : ses fonctions serverless peuvent être arrêtées après la réponse HTTP. La route api/index.ts est uniquement un test court. Le bot principal doit rester sur Railway, Render ou Fly.io.\n\n## Santé\n\nLe service long-running expose GET /healthz.\n
